05

TCP 3-Way Handshake

Capture SYN · SYN-ACK · ACK · read full TCP lifecycle
// TCP lifecycle captured — curl http://example.com SYN 192.168.1.65 → 192.168.1.254 Seq=0 Win=65535 MSS=1460 SACK_PERM SYN,ACK 192.168.1.254 → 192.168.1.65 Seq=0 Ack=1 MSS=1460 WS=64 ACK 192.168.1.65 → 192.168.1.254 Seq=1 Ack=1 // ↓ connection established HTTP GET /nonAuth/wan_conn.xml HTTP/1.1 // ↓ data exchange FIN,ACK — clean connection close (no RST observed)
Handshake parameters observed
  • MSS=1460 — Maximum Segment Size negotiated during SYN
  • Win=65535 — TCP window, unacknowledged data in flight
  • Multiple complete lifecycles — open → data → close → new SYN
  • Clean FIN,ACK teardown — no RST resets (healthy connection)
Bonus finding — Cloudflare CDN
  • example.com served via Cloudflare London (LHR)
  • CF-RAY: 9f3edbe12dd59df1-LHR
  • Cache Age: 13,903 seconds (≈3.8 hours)
  • Transfer-Encoding: chunked · Connection: keep-alive
⟫

Key learning: Every TCP connection on the internet — browser tabs, SSH, APIs — starts with this exact three-packet sequence. A RST instead of FIN indicates abrupt termination: firewall drop, application crash, or port scan detection.

Key observations
  • Full DORA completed in 206 milliseconds
  • Transaction ID 0xeebcfcff consistent across all 4 DORA packets
  • Discover/Request from 0.0.0.0 → broadcast — no IP yet
  • Router identifies client by MAC address before IP assigned

Key learning: DHCP must work before the client has an IP address — so it uses MAC-based identification and broadcast. The Transaction ID ties a Discover to its Offer when multiple devices request IPs simultaneously.

07

HTTP Plaintext Capture

Read raw HTTP headers · expose cookie in packet bytes
// HTTP headers read directly from packet hex dump GET /nonAuth/wan_conn.xml HTTP/1.1 Host: 192.168.1.254 Connection: keep-alive User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Accept: */* Accept-Encoding: gzip, deflate Accept-Language: en-GB,en;q=0.9,en-US;q=0.8 Cookie: urn=102... ← session token visible in plaintext
What was captured
  • BT Hub admin page polling every ~3 seconds via background AJAX
  • Full request headers readable directly from packet bytes
  • Browser identified: Edge on Windows 10 x64 (WebKit/537.36)
  • Cookie header visible in plaintext — session token exposed
  • Router responding with HTTP/1.0 — older embedded device version
Security implication
  • HTTP traffic is fully readable to anyone on the same network segment
  • Cookies, session tokens, credentials — all exposed without HTTPS
  • TLS encryption makes this data unreadable even if packets are captured
  • This is why modern browsers flag HTTP as "Not Secure"
⟫

Key learning: You just read a live Cookie header from raw packet bytes. This is exactly what a network-level attacker sees on an HTTP connection. HTTPS exists to prevent precisely this.
